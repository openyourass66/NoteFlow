# 音频复核循环：实现与验证边界

更新日期：2026-11-16。此功能为实验版本；本地主旋律识别和演奏仍可完全离线使用。

## 目标与入口

云端模型负责听辨原曲与单一乐器演奏的差异，本地模型负责从音频证据生成修正候选。云端不直接生成简谱，也不能用自由文本指令直接改写音符。

桌面入口为播放器旁的「音频复核…」，需已有乐谱。选取目标沿用该乐谱生成时的人声／乐器设置，复核范围默认前 20 秒，可手动选择或扩展为整段。仅点击上传操作后发起请求。默认最多 3 轮、24 次请求，调用上限可设置为 1–60 次，轮数最多为 3。

## 处理流程

1. 保存当前音符作为基线。演奏统一为钢琴，使用音符的原始秒数，不使用简谱排版的网格时间。
2. 将所选范围按最多 20 秒切片，每片包含原曲与演奏。原曲和演奏按同一时间轴裁切，转为 24 kHz 单声道 PCM16；片段之间插入 1 秒静音，并在请求中明确各段位置。
3. 云端返回 `pass`、`issues` 或 `uncertain`。问题必须包含片段内起止时间、问题类型和听辨理由。时间换算为全曲时间后再交给本地控制器。畸形 JSON、时间越界、矛盾状态、截断输出均不能用于修改或判定通过。
4. 本地重新提取 Basic Pitch 音高与起音证据、谐波起音包络、能量；配置了神经音高环境时，也使用 torchcrepe。云端的自由文字仅用于显示，修正器只处理已定义的问题类型。
5. 优先提出最多 8 处微调，同时按疑点范围重新解码乐句，形成多个可试听候选。乐句重建可增删音符，不受微调的 8 处限制；验证时序、音域和不重叠约束。选区外和跨越选区边缘的音符保持原样。自动循环每轮比较优先候选，其他候选留给用户选择。
6. 对每个发生改动的片段，云端听原曲、A、B，然后交换 A/B 顺序再听一次。两次都选择候选版本才允许采用；任一片段不支持改进，整轮候选不采用。听辨请求不透露哪一个是新版本。
7. 采用候选后重新检查所选范围。只有当前版本的所有片段都通过，才显示「所选范围的云端复核通过」。最后一轮仅采用修改但尚未复核时，显示达到轮数上限。

“交换顺序”用于发现顺序偏好，不能消除模型共同误判，也不是独立专家复核。片段音量只使用固定增益调整，不改变音高、速度或休止。

## 当前允许的局部修正

| 问题 | 本地处理 | 约束 |
| --- | --- | --- |
| 音高偏差 | 从当前音高上下 1–2 半音中选择证据较强者 | Basic Pitch 必须明确支持；有神经 F0 时也需一致；不能根据文字指定任意音高 |
| 错八度 | 尝试上下一个八度 | 混音中的乐器还需与附近主旋律音域相符，避免改成低音伴奏 |
| 起音节奏偏差 | 在现有起音前后最多 80 ms 内寻找明确的起音证据 | 不越过前一个音符，不缩短到不足 80 ms；尚不自动调整自由速度或整体节拍 |
| 同音碎裂 | 尝试合并不超过 120 ms 的同音间隙 | 音频不能静音，须有该音高支持，并且没有明显新起音；真实休止及重复音不能直接抹掉 |
| 乐句音高、节奏、碎裂、漏音 | 用疑点附近上下文重新解码音符，允许增删、拆分、合并 | 仅使用本地音频证据；节奏／连续性沿用已有局部音域；无可信音符时不生成候选 |
| 声部错误 | 显示问题，允许定位音符或重选声部 | 暂不自动切换主奏声部或重做分离 |

无法生成不同且有音频支持的结果时，显示具体原因。自动替换须获双顺序对照支持；未经一致确认的候选仍保留，可人工试听后明确应用。重建不会按照云端文字所说的秒数整体移动旋律，也不直接接受云端指定的音高。

## 根据复核结果改谱

结果窗口默认选中第一个可用候选。没有候选时，点击「生成候选」，用当前乐谱和本地音频重建最近一轮的疑点片段。生成过程可以取消，云端请求次数和乐谱保持原样。

在同一窗口点击「原曲」「修改前」或「候选」直接试听。第一次点击会准备三路对齐的音频，后续切换保留播放位置。满意后点「应用到简谱」，更新简谱和演奏并返回乐谱，可撤销、重做。「查看详情」提供最近一轮疑点、音符改动和处理原因，还可定位音符或导出记录。

手动应用记录为 `manual`，自动采用轮数保持原值。乐谱被编辑或撤销后，应用前需要重新生成候选。报告格式为版本 2。「导入复核记录」兼容版本 1，检查当前音符匹配后恢复反馈，候选根据当前音频重新生成。导入和本地操作保留既有云端用量及原始记录文件。

当前乐谱的复核结果保存在内存中。关闭结果窗口后，点「音频复核…」重新查看疑点和候选，点「重新复核…」进入上传配置。退出软件、切换项目或重新生成简谱时清空会话结果。只有手动导出才写入复核 JSON。

## 停止与恢复

- 判断不确定、前后对照矛盾、没有有证据的候选、候选重复时停止。
- 达到轮数或调用上限时停止；部分范围未检查不能显示通过。长曲目可能先耗尽调用预算。
- 网络、鉴权、限流、解析错误均不自动重试；失败的请求尝试也占用调用上限。音频准备失败可能在请求尝试阶段退出，因此显示次数可能高于服务商实际收到的次数。
- 网络操作使用可取消的异步 HTTP 流，单次整体期限约 120 秒，连接超时 15 秒。取消会关闭本地请求，已送达服务商的调用仍可能计费。
- 循环在内存中保留最近已采用的音符，取消或后续失败时返回该版本。桌面将本次采用的全部修改记为一个可撤销操作。
- 保存 `.noteflow` 会写入已应用的音符。复核记录可通过「查看详情」手动导出。

JSON 记录包含原始与最终音符、轮次、反馈、采用记录、停止原因及服务商提供的 Token 用量。`accuracy` 固定为 `null`，不把模型自评或调用次数转换为音准准确率。未收到服务商用量字段时不会编造费用估计。

## 服务与凭据

首版接入阿里云百炼 Qwen-Omni HTTP 接口，默认 `qwen3.8-omni-flash`。使用 `input_audio` Base64 WAV 和 SSE 文本回复；将原曲和演奏合成一个带明确段落位置的音频文件，也兼容单音频输入的 `qwen3-omni-flash`。不通过麦克风重新录制扬声器播放。

Base URL 需从百炼控制台复制，API Key 与地域一致。仅接受官方 DashScope 或业务空间 HTTPS 地址，拒绝重定向和第三方网关。使用系统直连网络，不自动读取代理环境变量。Key 仅在内存或启动时的 `DASHSCOPE_API_KEY` 环境变量中使用，配置文件只保存服务地址和模型。

接口依据：阿里云 [Qwen-Omni](https://help.aliyun.com/zh/model-studio/qwen-omni)、[Base URL](https://help.aliyun.com/zh/model-studio/base-url)、[Chat 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions/)。这些接口能力并不能证明模型具备可靠的逐音音乐听辨能力。

## 受控听辨检查

桌面弹窗中可点击「检查复核能力（6 次）」，上传本地生成的 8 秒已知旋律，并进行：

1. 正确旋律与钢琴演奏对照，允许音色不同。
2. 故意将中间数个音提高两个半音。
3. 故意将中间数个音降低一个八度。
4. 故意将连贯音符拆成有空隙的断奏。
5. 比较正确演奏和错音演奏。
6. 交换播放顺序后再次比较。

这六项检查不改变当前乐谱，仅上传内置素材。没有全部通过时，不建议依赖该模型自动修正真实乐曲。全部通过也只是进入真实混音验证的前提，仍需人工盲听和有标注的样本集。

开发命令 `python poc/check_audio_reviewer.py` 默认只在本地生成音频，报告状态为 `prepared`、调用次数为 0。加 `--send` 才调用服务。每次输出独立目录，保留四种对照 WAV 及 `calibration.json`。
